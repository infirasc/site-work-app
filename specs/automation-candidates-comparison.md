# 반복업무 자동화 후보 비교표

# ★ 이번 프로젝트 대상: 투심(투자심의) 보고서 자동화

> 최초에는 "토지 실거래 분석기"로 시작했으나, 효과 × 난이도 재검토 끝에 소비처(투심위)가 확정된 **투심 보고서 자동화**로 최종 교체됨. 아래 "솔직한 요약"과 비교표는 최초 3개 후보 검토 당시 기록이며, 최신 결정은 문서 하단 "확정 스펙 / MVP 결정" 섹션 참고.

평가일: 2026-07-22

## 솔직한 요약 (효과 × 난이도 매트릭스 결론 먼저 — 최초 3개 후보 검토 당시 기록)

> 아래는 하단 "효과 × 난이도 2x2 매트릭스" 분석의 결론을 가감 없이 먼저 적은 것입니다. 듣기 좋은 말은 뺐습니다.

- **셋 중 "그냥 만들면 바로 효과 있는" 후보는 없습니다.** 3개 모두 조건부입니다. 지금 이 문서만 보고 "효과 높음"이라고 확정할 수 있는 후보는 하나도 없다는 뜻입니다.
- **토지 실거래 분석기(현재 선택된 프로젝트)조차 "효과 높음"이 확정이 아니라 가정입니다.** 만들기는 제일 쉽지만, 결과물이 실제 협상·스크리닝 의사결정에 연결되지 않으면 그냥 "숫자 보여주는 툴"로 끝날 수 있습니다. 지금 시점에 그 연결고리(누가, 언제, 어디에 쓸지)가 정해져 있지 않다면 "효과 높음"이 아니라 "효과 미정"이 정확한 표현입니다.
- **Market Dashboard는 냉정히 말해 3개 중 가장 리스크가 큰 후보입니다.** 만들기 난이도는 중간이지만, 대시보드류는 "일단 만들어두면 누군가 볼 것"이라는 기대와 달리 실사용률이 낮은 경우가 흔합니다. 사용 시나리오를 못 박지 않으면 투입 대비 효과가 3개 중 제일 낮을 가능성이 있습니다.
- **DD 리포트 생성기가 사실 셋 중 효과 잠재력은 가장 큽니다.** 실제 딜(투자금 규모)에 직결되기 때문입니다. 다만 초안 어시스턴트로 범위를 좁혀도 여전히 난이도가 높고, 무엇보다 최종 판단은 AI가 못 하므로 "자동화 효과"를 시간 단축 이상으로 과대평가하면 안 됩니다.
- **결론**: 지금 선택(토지 실거래 분석기)은 "3일 안에 완성 가능"이라는 기준으로는 맞는 선택이지만, "업무 효과가 크다"는 근거는 아직 없습니다. 3일 프로젝트 완성 후 실사용 여부(실제로 이 숫자를 협상/스크리닝에 썼는가)를 반드시 확인해야, 이 매트릭스의 "효과 높음"이 진짜인지 착각인지 판가름됩니다.

## 부분 자동화 검토 — 개발부지 실사(DD) 리포트 생성기

전체 프로세스를 통째로 AI에 맡기기는 어렵지만, 아래처럼 "반복·규칙적인 조각"만 떼어내면 AI가 초안 작성자·조사 보조 역할로 도움을 줄 수 있습니다.

### AI가 도울 수 있는 반복 조각

| 작업 | 내용 |
|---|---|
| 공부서류 조회·파싱 | 등기부등본, 토지이용계획확인원, 지적도 등에서 소유자·지목·면적·근저당 금액 등 핵심 항목 추출 |
| 실거래가 수집·통계 | 주변 실거래가 자동 수집 후 평균/중앙값/최근 추이 계산 (후보 3의 실거래 분석기 로직 재사용 가능) |
| 규제 체크리스트 대조 | 용도지역별 허용 건축행위, 건폐율·용적률 등 정형화된 규칙과 자동 매칭 |
| 리포트 템플릿 채우기 | 정해진 서식(표지, 개요, 데이터 표)에 조사 결과를 자동으로 채워 넣는 초안 생성 |
| 누락 서류·자료 최신성 체크 | 필요한 서류 중 빠진 것, 발급일이 오래된 자료를 자동으로 표시 |
| 요약문 초안 생성 | 수집된 데이터를 바탕으로 "사실 관계 요약" 문단 초안 작성 (판단·결론 문장은 제외) |

### 사람이 반드시 해야 하는 판단 영역

| 작업 | 이유 |
|---|---|
| 리스크 심각도 평가 및 투자 여부 결론 | 여러 리스크를 종합해 우선순위를 매기는 것은 책임이 따르는 판단 |
| 애매한 인허가·법률 해석 (예외 조항, 재량 사항) | 규칙만으로 판단 불가능한 회색 지대 존재 |
| 현장 답사·육안 확인 사항 반영 | 문서로 확인 불가능한 물리적 상태(진입로 여건, 지반 등) |
| 협상 가격·조건 결정 | 전략적 판단이며 외부에 미치는 영향이 큼 |
| 최종 리포트 검토·승인 | 대외 제출/의사결정에 쓰이는 문서이므로 책임 소재상 사람 승인 필요 |

### 정리
AI는 "자료 취합 → 구조화 → 초안 작성" 단계까지 담당하고, 사람은 "리스크 판단 → 결론 → 최종 승인" 단계를 담당하는 분업 구조가 적절합니다. 즉, DD 리포트 자체를 자동화 대상으로 삼기보다는 **"DD 리포트 초안 어시스턴트"** 형태로 좁혀서 자동화하면 후보 2, 3과 비슷한 수준의 AI 적합도를 확보할 수 있습니다.

## 3일짜리 첫 실습 프로젝트 추천 — 3) 토지 실거래 분석기

| 기준 | 판단 |
|---|---|
| 빈도 | 보통 — 학습용으로도 반복 실행하며 개선하기 좋음 |
| 귀찮음 | 보통 — 하지만 데이터 소스가 국토부 실거래가 하나로 좁혀져 있어 3일 안에 끝을 볼 수 있는 범위 |
| AI 적합도 | 높음 — 파싱·통계·이상치 탐지 모두 규칙 기반이라 판단 로직을 따로 설계할 필요가 없음 |

**추천 이유(짧게)**
- 데이터 소스가 하나(공공 실거래가)라 3일 내 "입력 → 처리 → 결과" 전체 파이프라인을 완결할 수 있음
- 성공/실패 판단이 명확함 (숫자가 맞는지 검증하기 쉬움) → 실습 프로젝트로 성취감을 얻기 좋음
- 이후 후보 2(Market Dashboard)로 자연스럽게 확장 가능 (같은 데이터 파이프라인에 시각화만 얹으면 됨)

**처음엔 부담되는 후보**
- **1) 개발부지 실사(DD) 리포트 생성기** — 데이터 소스가 여러 개(등기, 지적도, 인허가, 시세)이고, 판단·요약 로직 설계까지 얽혀 있어 3일 안에 "완결된 결과물"을 내기 어려움. 첫 프로젝트보다는 실거래 분석기로 기초를 다진 뒤 확장 과제로 접근하는 것을 권장.

## 효과 × 난이도 2x2 매트릭스

기준: **효과** = 실제 업무 의사결정(딜 스크리닝, 협상, 리스크 판단)에 미치는 영향 / **난이도** = 데이터 소스 개수 + 판단 로직 복잡도 + 유지보수 부담

|  | **난이도: 쉬움** | **난이도: 어려움** |
|---|---|---|
| **효과: 높음** | ★ 3) 토지 실거래 분석기 *(조건부 — 아래 참고)* | 1) 개발부지 실사(DD) 리포트 생성기 — 딜 성사에 직결되어 효과는 크지만, 다중 소스·판단 로직 때문에 난이도가 높음 |
| **효과: 낮음** | (해당 없음) | 2) 상업용 부동산 Market Dashboard — 실제 의사결정과 연결되는 사용처가 정해져 있지 않으면 "보는 사람 없는 대시보드"로 전락할 위험 |

### "효과 높음 × 난이도 쉬움" 칸 검토 — 토지 실거래 분석기

이 칸에 들어간 후보는 **3) 토지 실거래 분석기 하나뿐**이라 다른 후보와 비교할 대상은 없지만, "정말 업무에 효과가 있는가"는 아래 3가지 조건이 충족될 때만 성립합니다. 조건이 빠지면 이 후보도 "효과 보통" 칸으로 내려갈 수 있습니다.

| 조건 | 충족 안 되면 생기는 문제 |
|---|---|
| 결과물이 실제 의사결정(협상가 산정, 매입 스크리닝)에 **직접 입력값**으로 쓰이는지 | 참고용 리포트로만 끝나면 "만들어두고 안 보는 자료"가 되어 효과가 사실상 낮음 |
| 다운계약·특수관계 거래 등 **이상치 필터링 로직**이 있는지 | 국토부 실거래가는 신고가 기준이라 필터링 없이는 벤치마크 신뢰도가 떨어짐 |
| 갱신 주기(월 단위)의 한계를 인지하고 **포지셔닝**했는지 | 실시간 협상 도구로 기대하면 실망 → "사후 검증·스크리닝 도구"로 범위를 명확히 해야 함 |

**결론**: 3일 프로젝트로 만들되, 완성 후 바로 "이 숫자를 실제로 어떤 의사결정에 쓸 것인지"를 먼저 정하고 시작하는 것을 권장합니다. 그래야 이 칸에 남아 있는 "효과 높음"이 실습용 성취감이 아니라 실제 업무 효과로 이어집니다.

## 후보 재선정 — 투자심의(투심) 보고자료 정리·가공 자동화

기존 3개 후보의 공통 결함은 "산출물을 실제로 누가, 언제 쓰는지"가 불확실하다는 것이었습니다. 사용자 확인 결과, **투심/보고 자료 취합**은 소비처(투심위·경영진 보고)가 이미 확정돼 있고, 병목도 판단이 아니라 **정리·가공**이라고 밝혀 — 앞의 3개보다 훨씬 근거 있는 후보입니다.

### 평가

| 기준 | 판단 |
|---|---|
| 빈도 | 투심 일정에 맞춰 반복 (회사 사이클에 따라 보통~높음) |
| 귀찮음 | 높음 — 본인이 직접 지목한 병목 지점 |
| AI 적합도 | 높음(조건부) — 서식·계산식이 고정돼 있다면 규칙 기반 작업에 가까움 |

### 효과 × 난이도 매트릭스 위치

**효과: 높음** (소비처 확정 — 매번 실제 회의에 제출됨) × **난이도: 낮음~보통** (자료 수집은 병목이 아니고, 이미 모인 데이터를 정해진 형식으로 옮기는 작업이 중심)

→ 지금까지 나온 후보 중 "효과 높음 × 난이도 쉬움" 칸에 가장 떳떳하게 들어갈 수 있는 후보입니다.

### AI가 도울 수 있는 조각 (정리·가공)

| 작업 | 내용 |
|---|---|
| 표준 템플릿 자동 채우기 | 취합된 원본 데이터(엑셀·문서)를 투심 보고서 표·섹션 구조에 자동 배치 |
| 반복 계산 자동화 | IRR, NOI, Cap Rate 등 정해진 공식의 계산을 자동 산출 (공식이 고정이라는 전제) |
| 서식·용어 통일 | 담당자마다 다른 표기/단위/소수점 자리 등을 일관되게 정리 |
| 이전 투심 자료 포맷 대조 | 직전 보고서와 구조·항목 누락 여부 자동 비교 |

### 사람이 반드시 해야 하는 부분
투자의견·리스크 코멘트 작성, 애매한 항목에 대한 판단, 최종 검토·승인 — 이 부분은 여전히 사람 몫입니다.

### 진행 전 확인해야 할 전제조건 (신중 검토)
- 투심 보고서 **템플릿(표·섹션 구조)이 매번 거의 동일**한가, 아니면 건마다 크게 달라지는가
- 정리에 들어가는 **계산식이 고정 공식**인가, 아니면 그때그때 가정치가 달라 판단이 섞이는가
- 원본 데이터가 오는 **형태**(엑셀/워드/구두 취합 등) — 자동 정리기의 입력 설계에 필요

위 전제가 맞다면, 이 후보가 지금까지 나온 것 중 가장 "빈 깡통이 아닌" 자동화 후보입니다. 다만 실제 투자 데이터를 다루는 만큼 3일 실습 범위로 바로 넣기보다, 템플릿 구조부터 먼저 확인하고 범위를 정하는 것을 권장합니다.

## 전제조건 확인 완료 — 확정 스펙

사용자 확인 결과 3가지 전제조건이 모두 충족되어, 이 후보는 "조건부 효과 높음"에서 **"검증된 효과 높음"**으로 격상합니다.

### 확정된 템플릿 항목
- 주변 실거래 및 감정평가 시세
- 매물 시세
- 공시지가 시세 대비 가격
- 토지면적
- 건물 연식
- 건물 규모
- 임차 현황: 총 임대인 수, 총 보증금, 총 월임대료, 총 관리비 내역
- 유동인구
- 엘리베이터 유무
- 주차장

### 확정된 계산식

**Cap Rate 산식 확정** (사용자 확인):
```
Cap Rate = NOI ÷ 매입가능가격
NOI = (총 월임대료 × 12) + (총 보증금 × 지역 환산율)      ※ 관리비 수익은 NOI에서 제외 (확정)
```
- 기준 분모는 감정가가 아니라 **매입가능가격**
- 보증금은 **지역·현시점 전월세 환산율**을 곱해 운용수익으로 환산해 NOI에 포함
- **관리비**는 운영비용/수익 어느 쪽으로도 NOI 계산에 넣지 않음 (확정)
- **환산율은 자동조회** (사용자 확인) — v1부터 외부 데이터 연동 필요

**개발이익 산식 확정** (사용자 확인):
```
개발이익 = 개발 후 가치 − 매입가능예상가격 − 개발비용

개발 후 가치 = 주변 신축(10년 이내) 건물의 ROI 기준으로 산정한 가치
개발비용   = 연면적 × 최근 평당 건축비 (자동조회)
```
- **평당 건축비도 자동조회** 대상 — 환산율까지 합치면 v1에 필요한 외부 데이터가 2개로 늘었습니다.
- **"주변 신축 10년 이내 건물의 ROI"는 v1에서 수동 입력으로 확정** (사용자 결정). 비교대상 건물 선정(반경, 연식, 용도 유사성)은 판단이 섞이는 영역이라 MVP 범위에서 제외하고, MVP 완성 후 별도 단계에서 자동화를 추가하기로 함.

기타 계산식 (변경 없음):
- 용적률 = 연면적 ÷ 대지면적 × 100
- 건폐율 = 건축면적 ÷ 대지면적 × 100

### 입력/출력 방식
- **입력**: 템플릿 항목은 워드/구두 취합 → 웹 입력 폼. 단, **환산율·평당 건축비는 자동조회**로 폼에 미리 채워짐(사용자가 필요시 수정 가능)
- **출력**: 웹 화면에 리포트 미리보기 + PDF 다운로드

### 재평가된 효과 × 난이도
**효과: 높음** (검증됨, 변동 없음) × **난이도: 보통** (환산율·건축비 자동조회 데이터 연동이 추가되면서, 애초 평가했던 "낮음~보통"에서 살짝 올라감)

솔직히 말씀드리면 — 외부 데이터가 없는 버전보다는 확실히 손이 더 갑니다. 다만 두 데이터 모두 "판단 없이 값만 가져오는" 조회형 데이터라 난이도가 크게 뛰지는 않고, 효과가 확실한 만큼 여전히 이 문서에서 가장 우선순위 높은 후보입니다.

> ⚠ 확인 필요: 환산율(전월세 전환율)과 평당 건축비를 **어느 소스에서 자동조회할지**는 아직 정해지지 않았습니다. 공공데이터포털 등 구체적 출처는 실제 구현 착수 시점에 함께 확인이 필요합니다 — 여기서 출처를 잘못 짚으면 신뢰할 수 없는 자동조회가 되므로, 지어내지 않고 착수 시 정확히 확인하겠습니다.

### 로드맵 확정 — MVP 먼저, 자동화는 이후 단계

사용자 결정: **MVP는 "주변 신축 건물 ROI"를 수동 입력으로 처리해 먼저 완성하고, 이후 단계에서 자동화를 추가**하는 순서로 진행.

**MVP(1차 구현) 범위**
1. **입력 폼**: 템플릿 항목 전부 입력받는 웹 화면 (환산율·평당 건축비는 자동조회 값으로 사전 입력 후 수정 가능, "주변 신축 건물 ROI"는 수동 입력)
2. **외부 데이터 자동조회**: 지역 전월세 환산율, 최근 평당 건축비 — 소스 확인 후 연동
3. **계산 엔진**: Cap Rate / 용적률 / 건폐율 / 개발이익 자동 산출 (산식 확정됨)
4. **리포트 렌더링**: 입력값 + 계산값을 정해진 리포트 레이아웃으로 웹에 표시
5. **PDF 출력**: 웹 리포트를 그대로 PDF로 내보내기

**MVP 이후(2차) 확장 범위**
6. "주변 신축 10년 이내 건물 ROI" 비교대상 자동 선정 및 산출 (반경·연식·용도 기준 정의 필요 — 판단 요소가 있어 후순위로 미룸)
7. (스트레치) 입력값 저장 → 과거 작성한 리포트 목록에서 다시 열람

외부 데이터 자동조회가 2개 추가되면서 처음 예상보다 약간의 손이 더 가지만, 여전히 판단 로직 없이 조회·계산·렌더링으로 끝나는 구조라 난이도 자체는 관리 가능한 수준입니다.
