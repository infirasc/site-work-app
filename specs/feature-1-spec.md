# Feature 1 — 핵심 지표 계산 엔진

근거 문서: [real-estate-report-automation-pitch.md](real-estate-report-automation-pitch.md), [real-estate-report-automation-flow.md](real-estate-report-automation-flow.md), [real-estate-report-automation-plan.md](real-estate-report-automation-plan.md)

## 갱신 이력
- 2026-07-23: 사용자가 제공한 "MVP 구현 시 계산 순서" 표를 반영해 NOI·Cap Rate·개발비용(TDC)·개발후가치(GDV)·개발이익(Development Profit)·Development Margin 공식으로 교체. 아래 결정 사항을 반영함.
  - Development Margin = Development Profit ÷ GDV × **100** (표의 "×10"은 오타로 확인, 100으로 처리)
  - NOI 공식의 "운영비" = 기존 "총 관리비 내역"과 같은 항목으로 처리 (계산에 안 쓰던 참고용 → 계산에 쓰는 필수 항목으로 승격)
  - TDC의 "토지매입비" = 기존 "매입가능예상가격"과 같은 값으로 처리 (별도 입력 추가 안 함)
  - GDV 계산에 필요한 "Exit Cap Rate"가 기존 "주변 신축 건물 ROI" 입력을 대체 (ROI 입력은 이제 안 씀)
- 2026-07-23 (앱 점검 후속 조치): 실제 구현을 점검한 결과 나온 이상치 처리 공백 두 가지를 메움.
  - **음수 검증 추가**: 원래 plan.md의 이상치 기준("음수(개발이익 제외)는 이상치")이 이번 구현 전까지는 빠져 있었음 — 필수 10개 항목에 음수를 넣어도 그대로 통과해 용적률·공사비가 음수로 나오는 등 말이 안 되는 결과가 "정상"으로 나왔음. 이제 10개 필수 항목 전부 음수면 정지하도록 검증을 추가함.
  - **GDV가 0이 되는 경우 처리**: 총월임대료·총보증금·총관리비가 모두 0에 가까워 NOI가 0이 되면 GDV(=NOI÷Exit Cap Rate)도 0이 되어 Development Margin(=Profit÷GDV) 계산이 0으로 나누기가 되는 지점이 있었음(예외로 죽음). 계산을 멈추지 않고 넘어가되, Development Margin 값 자리에 숫자 대신 `"산출 어려움"`을 담고, 그 사유를 `산출불가사유` 필드에 별도로 담아 반환하도록 변경. (자세한 표시 방식은 [feature-3-spec.md](feature-3-spec.md) 참고)

## 왜 이 기능부터인가
앱의 존재 이유(손으로 하던 수익성·개발이익 계산을 자동화)가 여기에 있고, 웹 화면·PDF는 이 계산 결과를 보여주는 껍데기이기 때문.

## 무엇을 하는 기능인가 (한 문장)
매물 관련 입력값을 받아 필수 항목 누락을 검증한 뒤, Cap Rate·용적률·건폐율·Development Profit·Development Margin 등 핵심 지표를 자동 계산해주는 기능.

## 입력

**필수 10개 항목** (하나라도 비거나 명백히 잘못되면 정지):

| 항목 | 비고 |
|---|---|
| 연면적 (m²) | |
| 건축면적 (m²) | |
| 대지면적 (m²) | 나눗셈 분모 — 0이면 정지 |
| 총 보증금 (억원) | |
| 총 월임대료 (억원) | |
| 총관리비 (억원, 연간 총액) | NOI에서 운영비로 차감. 원 기획서(plan.md)에서는 참고용이었으나, 이번 계산식 갱신으로 필수 항목이 됨 |
| 매입가능예상가격 (억원) | Cap Rate의 분모이자, TDC의 "토지매입비"로도 그대로 사용 (동일 값, 별도 입력 없음) — 나눗셈 분모이기도 하므로 0이면 정지 |
| 전월세 환산이율 (%) | 계산용 외부값. 자동조회 대신 지금은 수동 입력으로 대체 |
| 평당 건축비 (억원, m² 기준) | 계산용 외부값. 표기는 "평당"이나 계산식은 연면적(m²)을 그대로 곱함 — 원 기획서 표기를 그대로 따름. 수동 입력으로 대체 |
| Exit Cap Rate (%) | GDV 계산에 쓰는 새 값. 나눗셈 분모이므로 0이면 정지. 계산용 외부값으로 취급해 지금은 수동 입력으로 대체 |

**제거된 항목**: 주변 신축(10년 이내) 건물 ROI — 새 GDV 공식(NOI÷Exit Cap Rate)에서 더는 쓰이지 않아 feature 1 범위에서 제외. (전체 앱의 다른 문서/리포트에서 이 항목이 여전히 필요한지는 이 스펙 밖의 별도 확인 사항)

**참고용 항목** (계산에 안 쓰임, 비어도 진행): 주변 실거래 및 감정평가 시세, 매물 시세, 공시지가 시세 대비 가격, 건물 연식, 총 임대인 수, 유동인구, 엘리베이터 유무, 주차장 — 변경 없음

## 동작: 어떤 순서로 처리하나
1. 필수 10개 항목 검증 — 빈 값 / 숫자가 아닌 값 / **음수** / 0(대지면적·매입가능예상가격·Exit Cap Rate 등 분모 항목) / 계산불가(NaN·무한대) 등 명백한 오류가 있으면 어떤 항목이 문제인지 구체적으로 안내하고 즉시 정지
2. NOI = (총월임대료×12) + (총보증금×전월세환산이율) − 총관리비
3. Cap Rate = NOI ÷ 매입가능예상가격 × 100
4. 용적률 = 연면적 ÷ 대지면적 × 100
5. 건폐율 = 건축면적 ÷ 대지면적 × 100
6. 공사비 = 연면적 × 평당건축비
7. TDC = 매입가능예상가격(토지매입비) + 공사비
8. GDV = NOI ÷ Exit Cap Rate (Exit Cap Rate는 %값을 소수로 환산해 나눔 — 예: 6% → 0.06)
9. Development Profit = GDV − TDC (음수가 나와도 이상치가 아니라 정상 결과로 그대로 반환 — "사업성 없음"은 사람이 판단할 몫)
10. Development Margin = Development Profit ÷ GDV × 100. **단, GDV가 0이면 나눗셈을 하지 않고 값 자리에 `"산출 어려움"`을 담아 반환** (계산을 멈추지 않고 다음 단계로 넘어감 — NOI가 0일 때 발생 가능)

## 출력
- **핵심 5개 지표**: Cap Rate, 용적률, 건폐율, Development Profit, Development Margin
- **중간값 4개**: NOI, 공사비, TDC, GDV
- 금액(억원) 항목(NOI, 공사비, TDC, GDV, Development Profit)은 소수점 둘째 자리까지 반올림
- 비율(%) 항목(Cap Rate, 용적률, 건폐율, Development Margin)도 표기 일관성을 위해 소수점 둘째 자리까지 반올림 (기존 명세에 없던 규칙 — 이번에 새로 추가)
- 검증 실패 시: 계산 결과 대신, 문제 있는 항목을 구체적으로 지목하는 에러 메시지 반환 (에러 메시지의 정확한 형식은 아직 미정 — 별도 확인 필요)
- Development Margin이 `"산출 어려움"`으로 나온 경우: 왜 계산할 수 없었는지 사유를 `산출불가사유` 필드(`{필드명: 사유 문자열}`)에 함께 담아 반환

## 지금은 뺄 것 (화면·저장·꾸미기 등, 나중에 붙일 것)
- 웹 화면 리포트 렌더링(표지·목차 등 구성)
- PDF 다운로드 변환
- 계산 결과 저장 / 이력 조회
- 참고용 입력 항목(시세, 유동인구, 엘리베이터 유무, 주차장 등) 처리 — 리포트 표시용이지 계산에는 불필요
- 전월세 환산이율·평당 건축비·Exit Cap Rate 외부 자동조회 연동 — 지금은 셋 다 수동 입력값으로 대체
- Cap Rate·용적률·건폐율·Development Margin 등 항목별 상세 정상범위 판정 — 지금은 빈값/0/계산불가 같은 명백한 오류만 체크
