## 왜 이 기능이 다음인가
Feature 2(리포트 데이터 매핑)까지는 구조화된 JSON만 만들어줄 뿐, 사람이 읽기 좋은 형태로 보여주지는 않는다. 웹 화면·PDF를 만들기 전에, 지금 있는 8개 섹션 데이터를 사람이 바로 읽을 수 있는 줄글(마크다운)로 바꿔주는 단계가 먼저 필요하다.

## 무엇을 하는 기능인가 (한 문장)
Feature 2의 리포트 데이터를 8개 섹션 순서 그대로 마크다운 줄글로 바꾸고, Development Margin에는 규칙 기반 사업성 해석 라벨을 붙여서 보여주는 기능.

## 입력
- Feature 2(`map_report`)의 반환값 그대로: `{"ok": bool, "report": {...}, "산출불가사유": {...}}` 또는 `{"ok": False, "errors": [...]}`

## 동작: 어떤 순서로 처리하나
1. `report_result["ok"]`가 `False`면, 계산·매핑 단계에서 이미 만들어진 에러 메시지를 그대로 마크다운 목록으로 보여주고 끝냄 (여기서 새로 검증하지 않음 — Feature 1·2가 이미 검증을 끝냈으므로)
2. `ok`가 `True`면 8개 섹션(표지/핵심지표요약/부동산개요/시세정보/임차현황/입지특성/수익성분석/개발사업성분석)을 그 순서 그대로 마크다운 제목(`##`)과 목록으로 나열
3. 값이 숫자면 단위(억원/%/m²/명/면)를 붙이고, `"정보 없음"`·`"산출 어려움"` 같은 문자열이면 단위 없이 그대로 보여줌
4. 값이 `"산출 어려움"`인 항목은 바로 옆에 그 사유를 작은 글씨체(마크다운 기울임, `_(사유: ...)_`)로 덧붙임 — 지금은 웹 UI가 없어 "눌렀을 때 펼쳐지는 설명"을 각주 형태로 대신함. 나중에 웹 화면을 만들 때 이 자리를 그대로 클릭-펼침 UI로 바꿀 수 있게, 사유는 항상 별도 필드(`산출불가사유`)로 분리해서 갖고 있음
5. Development Margin 값을 규칙 기반으로 해석해 "사업성 해석" 라벨을 붙임 (핵심지표요약 섹션과 개발사업성분석 섹션 양쪽에 표시):

   | Development Margin | 라벨 |
   |---|---|
   | 0% 이하 | 사업성 없음 |
   | 0% 초과 ~ 50% 미만 | 보통 |
   | 50% 이상 ~ 100% 미만 | 권장 |
   | 100% 이상 | 매우 추천 |
   | 산출 어려움(값 자체가 없음) | 산출 어려움 |

   위 구간은 사용자가 정한 4단계 기준(0 이하/100 이상/50~100/1~50)을 이어붙이면서 생기는 빈 구간(0% 초과 1% 미만)을 "보통" 쪽으로 채워 넣어 구간이 끊기지 않게 한 것 — 정밀한 하한선이 정해지면 다시 조정 가능.
6. 이 라벨은 지금은 고정 규칙으로 생성하지만, 나중에 AI가 생성하는 코멘트로 교체할 수 있도록 해석 로직을 별도 함수(`interpret_margin`)로 분리해두고, 그 자리에 다른 해석기를 끼워 넣을 수 있게 열어둠 (구체적인 교체 방식은 이 스펙 밖 — AI 코멘트 기능을 실제로 붙일 때 별도 확인 필요)

## 출력
- 마크다운 형식의 문자열 하나. 지금은 콘솔 출력만 하고 파일로 저장하지 않음(Feature 1·2와 동일하게 "결과는 저장하지 않음, MVP 기준" 원칙 유지)
- 투자의견·리스크에 대한 자유 문장 코멘트는 생성하지 않음 — 오직 위 표의 고정 라벨만 붙임(feature-2-spec.md의 "판단 문구 없음" 원칙 중, Margin 라벨링에 한해서만 예외)
