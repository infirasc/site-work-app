# Feature 2 — 리포트 데이터 매핑

근거 문서: [real-estate-report-automation-flow.md](real-estate-report-automation-flow.md) 6단계, [real-estate-report-automation-plan.md](real-estate-report-automation-plan.md) 리포트 목차/제약, [feature-1-spec.md](feature-1-spec.md)

## 왜 이 기능이 다음인가
Feature 1(계산 엔진)은 핵심 지표만 계산해서 반환할 뿐, 리포트 형태로 조립하지는 않는다. 웹 화면 렌더링이나 PDF 변환을 만들기 전에, "계산 결과 + 나머지 입력값을 8개 섹션 리포트 구조로 채워 넣고 한 번 더 검증하는" 이 단계가 먼저 있어야 그 다음 단계들이 그릴 데이터가 생긴다.

## 무엇을 하는 기능인가 (한 문장)
Feature 1의 계산 결과와 나머지 입력값(참고용 포함)을 합쳐 리포트의 8개 섹션 구조에 값을 채워 넣고, 비어있거나 계산이 실패한 값이 있으면 무엇이 문제인지 구체적으로 알려주고 멈추는 기능.

## 입력
- **Feature 1 계산 결과**: Cap Rate, 용적률, 건폐율, Development Profit, Development Margin (핵심 5개) / NOI, 공사비, TDC, GDV (중간값 4개)
- **Feature 1이 이미 검증한 필수 입력값**: 연면적, 건축면적, 대지면적, 총보증금, 총월임대료, 총관리비, 매입가능예상가격, 전월세환산이율, 평당건축비, Exit Cap Rate
- **참고용 입력값 8개** (계산엔 안 쓰이던 것, 비어 있어도 됨): 주변 실거래 및 감정평가 시세, 매물 시세, 공시지가 시세 대비 가격, 건물 연식, 총 임대인 수, 유동인구, 엘리베이터 유무, 주차장
- **표지용 정보**: 주소지, 작성일

## 동작: 어떤 순서로 처리하나
1. **매핑 전 검증** — 필수 입력값과 Feature 1 계산값이 하나라도 비어있거나(null) 계산 실패(NaN·무한대) 상태면, 어떤 항목인지 구체적으로 표시하고 즉시 정지. (Feature 1에서 이미 걸러졌겠지만, 매핑 직전에 한 번 더 확인하는 안전장치)
2. 참고용 입력값 중 비어있는 항목은 "정보 없음"으로 치환
3. 아래 8개 섹션에 값을 배치
   1. 표지 — 주소지, 작성일
   2. 핵심 지표 요약 — Cap Rate, 용적률, 건폐율, Development Profit, Development Margin (숫자만, 판단 문구 없음)
   3. 부동산 개요 — 연면적, 건축면적, 대지면적, 건물 연식, 용적률, 건폐율
   4. 시세 정보 — 주변 실거래·감정평가 시세, 매물 시세, 공시지가 대비 가격, 매입가능예상가격
   5. 임차 현황 — 총 임대인 수, 총보증금, 총월임대료, 총관리비
   6. 입지 특성 — 유동인구, 엘리베이터 유무, 주차 가능 면수
   7. 수익성 분석 — NOI, Cap Rate
   8. 개발 사업성 분석 — TDC, GDV, Development Profit, Development Margin
4. 투자의견·리스크 코멘트 같은 판단 문구는 넣지 않음 (plan.md의 "판단은 사람 몫" 제약을 그대로 유지). **단, 2026-07-23 앱 점검 이후 사용자 결정으로 Development Margin에 한해 규칙 기반 사업성 해석 라벨을 붙이기로 함 — [feature-3-spec.md](feature-3-spec.md) 참고. 이 예외는 Margin 라벨링에만 적용되고, 그 외 투자의견·리스크 코멘트는 여전히 넣지 않음.**

## 출력
- 8개 섹션이 모두 채워진 리포트 데이터 구조 — 다음 기능(Feature 3 렌더링)이 그대로 가져다 쓸 수 있는 형태
- 검증 실패 시: 리포트 데이터 대신, 문제 있는 항목을 구체적으로 지목하는 에러 메시지 반환 (정확한 형식은 Feature 1과 마찬가지로 아직 미정 — 별도 확인 필요)
- Feature 1이 `산출불가사유`를 반환한 경우(Development Margin이 `"산출 어려움"`인 경우), 그 값을 그대로 다음 기능에 전달함(값 자체를 판단하거나 지우지 않음)

## 지금은 뺄 것 (화면·저장·꾸미기 등, 나중에 붙일 것)
- 실제 웹 화면 렌더링(레이아웃, 스타일, HTML/CSS)
- PDF 변환
- 결과 저장 / 이력 조회
- 참고용 값의 표기 형식 가공(예: 엘리베이터 유무 표시 방식 등) — 지금은 입력받은 값 그대로 사용
- 리포트 문구 다듬기·설명 텍스트 추가 — 숫자만 채우고 판단 문구는 넣지 않는 원칙 유지
